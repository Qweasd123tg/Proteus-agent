# Ожидаемый Результат

Уточнено с владельцем 2026-10-01.

Proteus — конструктор для собственных алгоритмов и сборок агентов.
Первый рабочий пример — близкая реконструкция обычного сценария Codex.
Критерии этой сборки и критерии самого конструктора разделены ниже.

## Результат Для Конструктора

1. Рабочая сборка пригодна для согласованных повседневных задач.
2. Отдельную часть сборки можно полезно заменить через module и config;
   виден небольшой радиус изменений и сохраняется корректность границ.
3. Собственные алгоритмы и сочетания не требуют соответствия Codex.
4. Сборка и проверки воспроизводятся локально, ограничения перечислены явно.

## Критерии Сборки Codex

В выбранном обычном сценарии пользователь не замечает существенной разницы
с Codex. Сравнение на задачах подтверждает совпадение результатов и расхода.

Полное воспроизведение всех мелких фич Codex не требуется.
Текущий статус и уже известные ограничения находятся в [scope.md](scope.md).

## Что Значит Подтвердить Совпадение

На одинаковых записанных model/tool outcomes сравниваются requests,
действия, изменения history и terminal result. Нормализуется только явно
описанная недетерминированность, например ids и timestamps.

На живых задачах фиксируются версии обоих runtimes, модель и её настройки,
provider, исходный репозиторий, tools/permissions и условия cache.
Повторения позволяют отделить различие runtimes от вариативности самой
модели. Учитываются неудачные попытки и весь расход, включая внутренние
model calls, retries и peers, если они входят в сценарий.

Цель — совпадение результатов и расхода. Численный допуск для live измерений
этим документом не назначается. Его нужно определить до оценки вместе
с корпусом задач и количеством повторений. Денежные суммы опираются на
provider cost или одну зафиксированную таблицу цен.

## Граница Следующего Решения

Для сравнения сборки Codex ещё нужно определить обычный сценарий и исключения, pinned
версию Codex, интерфейс оценки и правила измерения. Эти детали пока
не являются согласованным перечнем feature work.

Текущая работа — доведение обычного цикла Codex на Proteus через проверяемые
расхождения с эталоном. Конкретные изменения выбираются с владельцем отдельно;
каталог возможностей сам по себе не является планом этого этапа.

Живое сравнение задач и расхода оставлено на последующий этап; оно остаётся
критерием проверки сборки Codex, но не блокирует текущую работу над каркасом.

Работы по переходу межагентного обмена на A2A отложены владельцем. Они не
входят в текущий этап и возобновляются только по отдельному решению.
Действующим backend AgentControl остаётся local stdio.

Ориентир для приложения — Codex App по выбранным владельцем экранам: спокойная
тёмная сиренево-серая палитра, компактная навигация, свободная лента чата,
единые скругления и вкладки панелей. Переходы не должны дёргать содержимое.
Основной клиент остаётся приложением на Leptos/Tauri. Расширения интерфейса
сохраняют независимый жизненный цикл. Функции прежнего Inspector постепенно
переносятся в расширения этого приложения: часть диагностических экранов уже
встроена, полный перенос ещё впереди. Представление инструментов, настроек
и анализа будет развиваться внутри основного приложения.

Расширения интерфейса развиваются независимо от модулей агента. Загрузчик и
панели, включая квоту подписки, уже используют самостоятельные пакеты расширений
и публичные API. Новые панели подключаются через конкретные договоры данных.

Проверки выполняются локально. CI отключён по решению владельца и
не является условием завершения.
