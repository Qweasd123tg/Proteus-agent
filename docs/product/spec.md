# Замысел Proteus

Уточнён владельцем 2026-09-05.

## Для Чего Нужен Конструктор

Исходная потребность — заменить compactor в Codex. Сложность этой правки
привела к идее собственного конструктора агентов: увидеть новый алгоритм,
написать узкий модуль и включить его в рабочую сборку.

Ценность Proteus — небольшой радиус изменений при замене поведения:

```text
идея -> module implementation -> выбор в profile -> проверка результата
```

Собственные алгоритмы и сочетания понравившихся частей разных агентов —
обычное назначение платформы. Например, можно совместить отдельные решения
Codex и OpenCode в своём профиле.

## Архитектурный Принцип

```text
Core -> Contract -> Module Implementation

authority(module) = authority(slot, invocation_context)
```

Core владеет сборкой, authority, lifecycle и общими границами исполнения.
Алгоритм принадлежит module. Slot задаёт typed contract и способ выбора
implementation; component — внешний process с одним или несколькими exports.
Profile связывает конфигурацию и выбранные modules.

Новая implementation существующего slot подключается через его contract.
Новый slot нужен, когда появляется отдельная общая host-owned обязанность;
его правила описаны в
[slot-governance.md](../architecture/slot-governance.md).

Нельзя гарантировать, что любой будущий алгоритм поместится в сегодняшние
contracts. Если идея требует другой общей semantics, границу можно изменить.
Основанием служит конкретная потребность или дефект, включая собственные
идеи владельца. Реконструкция чужого агента для этого не обязательна.

Замена модуля не должна менять его protocol authority. Совместимость
поведения составных модулей проверяется отдельно: одинаковый transport
не гарантирует одинакового понимания history и metadata.

## Роль Реконструкций

Реконструкция — экзамен конструктора на известном полезном поведении.
Первый выбранный экзамен — Codex в обычной работе с кодом.

Владелец должен пользоваться этой сборкой на Proteus и не замечать
существенной разницы. Проверки на задачах должны подтверждать совпадение
результатов и расхода. Полная копия всех мелких возможностей Codex не нужна.

Получившиеся модули и профили могут стать первыми примерами для сообщества.
Готовая удобная сборка допустима; её implementations имеют те же права, что
любые другие. Имя `codex` само по себе не доказывает совместимость.

Свои улучшения и смешанные profiles описывают отличия явно и сохраняют
отдельную идентичность от сборки, на которой проверяется совпадение с Codex.

## Завершение Основного Этапа

Нужны два результата: пройденный экзамен обычного сценария Codex и
подтверждённая возможность полезно заменить отдельную часть обычным модулем.
После этого основная работа переходит к использованию конструктора и
развитию modules. Новые будущие идеи могут потребовать новых contracts.

Точное текущее состояние — в [scope.md](scope.md), критерии результата —
в [roadmap.md](roadmap.md). Архитектурные правила и ограничения описаны
в профильных справочниках.
