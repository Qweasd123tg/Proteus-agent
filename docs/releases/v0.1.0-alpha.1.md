# Proteus v0.1.0-alpha.1

Статус: release candidate. Код и локальные gates подготовлены; публичным
релизом версия становится только после успешного CI и публикации тега
`v0.1.0-alpha.1`.

## Что Входит

- process-only module runtime: Core выбирает typed `slot/module_id`, а
  реализация живёт во внешнем executable;
- Component Runtime v2 / strict wire protocol v3 с несколькими exports одного
  persistent process, callbacks, адресной отменой и lazy restart;
- process contracts для workflow, search, memory, context, context provider,
  policy, patch, compactor, tool exposure, renderer и tools;
- canonical session journal, cold history, prompt replay и side-effect-free
  workflow replay;
- CLI `proteus`, reference worker, HTTP/SSE app-server, Leptos chat и отдельный
  Inspector;
- единый `AssemblyPlan`: `proteus inspect plan` проверяет точные selections,
  components и export authority до запуска workers, а runtime публикует план
  вместе с соответствующим registry;
- versioned atomic developer install из `proteus` и
  `proteus-reference-worker` без dylib/plugin loader;
- внешний Python `Workflow` demo, который подключается config-ом без правки
  core;
- Linux CI и изолированный release smoke.

## Быстрая Проверка Без Внешнего API

Из корня checkout-а:

```bash
./scripts/alpha-smoke.sh
```

Сценарий создаёт временные install/config/runtime каталоги, собирает release,
выполняет `init safe`, `doctor`, fake-model turn, topology check и полный turn
через внешний Python workflow. Отдельно проверяется, что `inspect plan`
возвращает готовый чертёж установленного профиля. Пользовательские `~/.proteus`,
`~/.config/Proteus-agent` и `~/.local/bin` не изменяются.

Обычная developer-установка:

```bash
./install.sh
proteus init coding
proteus doctor
proteus inspect plan
```

Для собственной изолированной раскладки installer принимает
`PROTEUS_BIN_DIR`, `PROTEUS_HOME` и `PROTEUS_CONFIG_HOME`.

## Внешний Component Demo

```bash
proteus \
  --config examples/configs/proteus.process-agent.example.toml \
  "explain this profile"
```

Профиль выбирает `workflow/python_agent_loop`; executable
`examples/modules/agent-worker/agent.py` выполняет callbacks к context, model
и tools host-а. Если worker не запустился или нарушил contract, turn
завершается ошибкой: builtin fallback для этого `module_id` нет.

## Границы И Известные Ограничения

- Alpha поддерживается как Linux developer release из checkout-а; готовые
  переносимые бинарные архивы пока не публикуются.
- Process boundary не является OS sandbox. Configured workers доверенные и
  имеют права пользователя; подробности — в [SECURITY.md](../../SECURITY.md).
- Model provider adapters и `SubagentRunner` пока core-owned. Это явно
  учтённые следующие contract decisions, а не второй module ABI.
- Wire/config/storage surfaces pre-release и могут меняться атомарно без
  compatibility shims.
- Reference worker — dogfood implementation, не default/standard pack и не
  получает дополнительных прав.
- App-server рассчитан на loopback; это не production-ready public service.
- Marketplace, package manager, protocol freeze, uniform sandbox и hot reload
  в эту версию не входят.

## Release Gate

Перед публикацией тега должны быть зелёными:

```bash
cargo fmt --all --check
cargo test --workspace
(cd clients/web && env -u NO_COLOR trunk build --locked)
(cd clients/inspector && env -u NO_COLOR trunk build --locked)
./scripts/alpha-smoke.sh
git diff --check
```

Workflow `.github/workflows/ci.yml` повторяет Rust, client и isolated-install
gates на Linux. Публикация тега остаётся отдельным внешним действием после
успешного CI на release commit.
