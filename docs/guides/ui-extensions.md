# Расширения Клиента

UI Proteus — сменная витрина возможностей агента. Расширение клиента является
самостоятельным JavaScript ES module с JSON-манифестом. Его установка,
расположение, состояние и lifecycle принадлежат клиенту. Core, process workers,
profiles и runtime slots ничего не знают о панелях или их регистрации.

Расширение может работать автономно, обращаться к своему сервису обычным
browser API или использовать явно предоставленный клиентом интерфейс агента.
Одна и та же backend implementation доступна другим UI, CLI и headless-клиентам.
UI-пакет не обязан поставляться вместе с модулем агента и не выбирается по
`module_id`.

## Использование

В правой области чата откройте «Расширения». Там можно включать и отключать
панели, менять их порядок стрелками, удалять их из списка и добавлять пакет
по URL его манифеста. Нажатие на заголовок панели сворачивает её.
Состояние и порядок сохраняются в localStorage данного клиента.

Поставляются два независимых примера:

- «Сборка агента» читает публичный `GET /config`, показывает профиль и
  зарегистрированные инструменты. Обновляется при открытии панели и кнопкой
  «Обновить». Ошибка подключения отображается внутри панели.
- «Заметки» хранит текст в клиенте и не использует агента; включается в списке
  расширений. Заметки общие для этого клиента, без привязки к проекту или сессии.

Удаление панели из списка сохраняет её данные. «Восстановить список поставляемых
расширений» заменяет состав, порядок и состояние панелей содержимым поставляемого
каталога; данные самих расширений остаются. Повреждённые настройки не исправляются
молча: клиент показывает ошибку и предлагает это явное восстановление.

План, контекст, сессия и поведение существующих боковых областей сохранены.
Первое место подключения расширений — панели правой области web/desktop чата.
Существующие элементы UI пока не переводились в пакеты расширений.

## Пакет

Каталог может состоять из двух файлов:

```text
my-panel/
  extension.json
  panel.js
```

`extension.json`:

```json
{
  "apiVersion": 1,
  "id": "my-panel",
  "name": "Моя панель",
  "description": "Самостоятельная панель клиента",
  "entry": "./panel.js",
  "requires": []
}
```

`panel.js`:

```javascript
export function mount({ root, storage, signal }) {
  const input = document.createElement('textarea');
  input.setAttribute('aria-label', 'Текст');
  input.value = storage.get('text') ?? '';
  input.addEventListener('input', () => storage.set('text', input.value), { signal });
  root.append(input);
}
```

Раздайте папку статическим HTTP-сервером и добавьте URL `extension.json` в
клиент. Для отдельного origin сервер должен разрешать CORS для манифеста,
entry и импортов; JavaScript отдаётся с JS MIME type. Пересборка агента,
Leptos или desktop для такого подключения не нужна. После изменения кода
пакета перезагрузите клиент; hot reload внешних пакетов отсутствует.

Встроенные примеры лежат в `clients/web/extensions/agent-info` и `notes`.
`catalog.json` задаёт начальный список; после пользовательских изменений
используется сохранённый список. Trunk копирует каталог расширений, а desktop
встраивает те же assets. Dev-сборка следит за исходниками встроенных пакетов.
Установка из локального архива/папки и каталог пакетов с поиском пока не реализованы.

## Контракт UI API v1

Типы: `clients/web/extensions/api.d.ts`. Неизвестная версия или неизвестные поля
манифеста отклоняются; старого compatibility reader нет.

Entry экспортирует `mount(context)`. Context содержит:

| Поле | Договор |
|---|---|
| `root` | Собственный `ShadowRoot` панели; клиент владеет внешним заголовком и размещением |
| `services` | Только интерфейсы из `requires`; отсутствие интерфейса блокирует эту панель до исполнения entry |
| `storage` | `get/set/remove` строковых значений в пространстве `id` расширения |
| `signal` | Отмена при отключении, сворачивании панели, удалении, ошибке mount или закрытии представления |

`mount` возвращает `undefined`, функцию очистки или Promise одного из этих
значений. DOM listeners и fetch связываются с `signal`; собственные timers и
подписки освобождаются в функции очистки. Она вызывается один раз. Если панель
отключена во время загрузки entry, mount не вызывается; если отключена во время
асинхронного mount, signal отменяется сразу, а поздняя функция очистки выполняется
при завершении mount. Extension обязан завершать mount и учитывать отмену.
Ошибка загрузки/mount одной панели не останавливает соседние панели или чат.

Shadow DOM отделяет оформление содержимого от CSS остального клиента. Панель
наследует общие переменные цветов, шрифтов и скруглений, например `--text-main`,
`--text-muted`, `--bg-panel`, `--accent-blue`, `--font-sans`, `--radius-inner`.
Оболочка задаёт небольшой базовый стиль; пакет может добавить собственный CSS.

## Доступ К Агенту

Общий загрузчик `host.js` получает интерфейсы от клиента через
`mountExtensions(root, serviceFactories)`. У него нет зависимости от агента.
`web-adapter.js` связывает конкретную витрину с её HTTP transport и предоставляет
единственный текущий интерфейс `agent.config.read`:

```javascript
const config = await services['agent.config.read'].read();
```

Для его использования укажите `"requires": ["agent.config.read"]` в манифесте.
Ответ — неизменённый JSON публичного `GET /config`. Client transport добавляет
credential и связывает HTTP fetch с lifetime панели; расширение не получает
credential через этот интерфейс. Другой клиент может предоставить тот же
интерфейс своим transport-адаптером. Автономный пакет использует пустой `requires`.

Новые действия и источники данных добавляются через конкретные договоры клиента
или публичный API агента. Здесь нет нового behavior slot, регистрации UI внутри
worker-а или универсального вызова внутренностей modules. Данные квоты подписки
Codex текущим API не предоставляются; панель лимитов пока не реализована.

## Проверка

```bash
node --test clients/web/tests/extensions/*.test.mjs
cargo test --manifest-path clients/web/Cargo.toml --locked
cd clients/web
trunk build --locked
```

Из корня репозитория после сборки backend и web:

```bash
python3 clients/web/tests/extensions_browser.py
```

Нужны Firefox и geckodriver (`PATH`, `GECKODRIVER` или существующий Selenium
cache). Smoke использует отдельный browser profile, временные файлы и настоящий
app-server с fake-моделью. Проверяет authenticated `/config` через Leptos,
сохранение заметок/порядка, подключение внешнего пакета без сборки, отмену и
очистку при отключении/сворачивании, а также загрузку в другой странице без
агента. Скриншот сохраняется в `/tmp/proteus-ui-extensions.png`.
