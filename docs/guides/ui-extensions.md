# Расширения Интерфейса

## Принцип

Приложение Proteus расширяется независимыми расширениями интерфейса. Каждое
расширение — пакет JavaScript с JSON-манифестом. Приложение управляет его
установкой, расположением, состоянием и жизненным циклом. Core и модули агента
не зависят от панелей приложения и их регистрации.

Расширение может работать автономно, обращаться к своему сервису обычным
API браузерного движка или использовать предоставленный приложением интерфейс
агента. Тот же API агента может использоваться через CLI и без интерфейса.
Расширение интерфейса не обязано поставляться вместе с модулем агента и не выбирается по
`module_id`.

## Расширения настроек и поля ввода

Настройки, диагностика и селекторы поля ввода используют тот же контракт
расширений и жизненный цикл, что и устанавливаемые панели.
`clients/app/ui/ui/modules/catalog.js` явно регистрирует поставляемые реализации;
Rust предоставляет состояние и команды через адаптер `app/client_modules.rs`.
Приложение предоставляет расширению только интерфейсы из `requires`, которые
поддерживаются в текущей сборке.

`surfaces` принимает `compact`, `workspace`, `settings`, `composer-model`,
`composer-access`. Без `surfaces` пакет получает `compact` и `workspace`.
Для `settings` поле `navigation: {group: "agent" | "settings" | "diagnostics", icon: "..."}`
задаёт блок навигации («Агент», «Интерфейс» или «Диагностика») и значок. Страница появляется после включения пакета; entry
загружается при первом открытии. Переключение разделов и выход из настроек
сохраняют форму; выключение/удаление вызывает abort и disposer.
Селекторы композера — отдельные позиции с выбором одной реализации через
«Использовать». Если выбранное расширение выключено или удалено, позиция остаётся
пустой до явного выбора; режим доступа и модель агента не меняются.

Встроенные страницы внешнего вида, чата, клавиатуры и три диагностические
страницы можно выключить. Управление расширениями обязательно и не удаляется.
Повреждённые настройки показывают ошибку и позволяют явно восстановить
встроенный набор. Выбор и включение хранятся в `proteus.ui.modules`; данные
пакетов остаются в собственных namespace. Обязательные встроенные страницы не
входят в этот выбор: их можно не указывать, но нельзя выключить. Старого
переключателя плотности нет: компактная геометрия применяется всегда.

Блок «Агент» — обязательные встроенные страницы по слотам сборки: модель,
рабочий цикл, контекст, сжатие истории, инструменты, права и подтверждения,
правки файлов, поиск, память, обработчики и история изменений. Каждая страница показывает
реализации слота из профиля и параметры выбранного модуля: значения
`module_config` редактируются строками по типу текущего значения либо как JSON.
Все страницы работают с одним черновиком; панель внизу показывает изменённые
разделы и сохраняет их вместе через `agent.config.builder`. Сервер сначала
собирает и проверяет новую сборку и только потом записывает профиль.
Неправильный JSON или число блокирует сохранение. Схем параметров у модулей
пока нет, поэтому форма строится по уже заданным значениям. «История
изменений» показывает, что поменяло каждое сохранение, и загружает
заменённое им состояние в тот же черновик; откат сохраняется общей кнопкой.

Интерфейсы `client.preferences` и `client.composer` предоставляют `read`, `set`
и `subscribe` (типы — `clients/app/ui/extensions/api.d.ts`). Настройки устройства
записываются до изменения состояния; ошибка хранения оставляет прежнее значение.
Выбор модели, effort и доступа проходит существующие команды app-server.
`client.diagnostics.mount` уже встраивает в приложение расход/контекст,
анализ, сборку и архитектуру. Эти экраны пока используют код
`clients/app/diagnostics` и его API; подключение наследуется от основного
окна. Полный перенос функциональности прежнего Inspector в самостоятельные
расширения интерфейса ещё не завершён.
`client.modules.mount` предоставляет управление реестром. Пользовательский
диагностический пакет может рисовать собственный экран и
запрашивать поддержанные `agent.*` интерфейсы.

Пример манифеста самостоятельного пункта диагностики:

```json
{"apiVersion":1,"id":"my-diagnostics","name":"Моя диагностика",
 "description":"Состояние агента","entry":"./page.js",
 "requires":["agent.config.read"],"surfaces":["settings"],
 "navigation":{"group":"diagnostics","icon":"analysis"}}
```

`mount({root, services, signal, surface})` получает `HTMLElement` в настройках
и композере, `ShadowRoot` в панели. Код не должен предполагать конкретный тип
root. Расширение может поставлять несколько поверхностей; каждая получает собственный
mount и disposer. Установка процессных модулей агента или серверных пакетов
через этот контракт не выполняются.

## Использование

Рабочая область содержит одну или две группы одинаковых вкладок: чат
и инструменты. На первом запуске открыт только чат; остальные включённые
рабочие инструменты доступны через «+». Настройки и системные разделы открываются
отдельным экраном и не появляются в списке вкладок.
Кнопка в шапке делит область или объединяет
группы. Стрелка рядом с «+» переносит выбранную вкладку в соседнюю группу;
туда же можно перетащить её за название. Разделитель меняет пропорции, двойное
нажатие или Home возвращает равные размеры; ←/→ меняют пропорцию с клавиатуры.
Порядок, выбранные вкладки и пропорции сохраняются на устройстве.

Стрелки и Home/End переключают вкладки, Delete закрывает выбранную,
Alt+←/→ меняют порядок внутри группы. Escape отменяет перетаскивание без записи.
При закрытии последней вкладки второй группы области объединяются; в пустой
единственной группе остаётся выбор вкладок. Закрытие чата скрывает его
представление, сохраняя сессию и выполняемый ход. Названия обрезаются многоточием,
строка вкладок прокручивается. Крестик всегда виден, наведение подсвечивает всю
вкладку без нижней полосы и изменения ширины. Шапка показывает проект,
название содержимого находится во вкладке.

Содержимое зарегистрированной вкладки не меняет DOM-родителя при переносе между
группами: сохраняются iframe, черновик и прокрутка. Настройки и чат остаются
смонтированными при переключении. Отдельный экран настроек скрывает рабочую
область, сохраняя вкладки, разделение и черновик. Таймер активности и
автопрокрутка чата при этом приостанавливаются. «Вернуться к работе» и история
браузера восстанавливают выбранные вкладки; явная команда открытия чата выбирает чат.
Смена сессии обновляет только
сессионные экземпляры расширений и освобождает принадлежащие им вкладки;
раскладка рабочей области остаётся. При узком окне две области сохраняют минимум
320 пикселей каждая; доступна горизонтальная прокрутка рабочей области.

В «Настройки» → «Расширения» можно включать и отключать пакеты, менять порядок,
удалять из списка и добавлять по ссылке. Порядок меняется перетаскиванием за
ручку слева: соседние строки плавно сдвигаются, отпускание сохраняет порядок,
Escape отменяет перенос. При уменьшении движения сдвиг мгновенный. Ручка
также поддерживает ↑/↓ с клавиатуры.

Основные встроенные расширения находятся отдельно в сворачиваемом блоке
«Настройки → Расширения → Встроенные расширения»; устанавливаемые пакеты идут своим списком.
Настройки имеют собственную боковую навигацию, заменяющую список сессий.
Выбор пакета с `settings` открывает его параметры в той же области
содержимого. Возврат к списку и смена раздела сохраняют форму; выбор другого
пакета или отключение завершают её runtime. Escape сначала закрывает выпадающий
список, затем параметры расширения, не отменяя ход агента.
Закрытие вкладки расширения сохраняет его экземпляр, DOM и данные. Отключение
пакета завершает runtime. Переключение и перенос вкладок не перечитывают файлы
и не запускают новые запросы лимитов. `location` в host API остаётся подсказкой,
пользователь управляет фактическими группами через общие вкладки.
Внизу слева находятся настройки; отдельной страницы истории нет, сессии
выбираются в боковом списке. Управление пакетами вынесено в
«Настройки → Расширения», диагностические экраны — в группе «Диагностика».
Списки выбора модели и доступа, обычные `select`, меню вкладок, виджетов и
контекстные меню используют общую подложку, отступы и типографику
`clients/app/ui/ui/choice.css`. Длинные названия переносятся; пояснение располагается
отдельной строкой, выбранный пункт отмечается галкой. У `option` можно задать
`data-description` для пояснения; существующий `title` также читается, включая
его клиентскую проекцию `data-ui-tooltip`. Те же правила действуют в диагностике
и Shadow DOM расширений. Значение и события `input`/`change` остаются у исходного
`select`, поэтому оформление не заменяет привязки полей формы.

Компактные интерактивные виджеты включённых расширений находятся под полем ввода.
**Настройки → Расширения → нужное расширение → Расположение виджета**
позволяет независимо выбрать для каждого виджета поле ввода, верхнюю панель или
скрытие. Общий переключатель размещения отсутствует. Настройки расположения
доступны и у расширений без собственного settings entry. Иконку можно удержать
и перенести между полем ввода и верхней панелью, включая пустую верхнюю область;
отпускание сохраняет размещение, Escape восстанавливает исходное. ПКМ открывает
меню перемещения и скрытия; у пакета с workspace также доступно открытие вкладки.
Нажатие открывает соответствующую вкладку, если пакет её объявляет. Виджет и вкладка
используют один экземпляр расширения: перенос не перезапускает entry и не добавляет
опросов backend. Если расширение не заполнило `compact`, отображается общая иконка.
Подсказки кнопок показываются при наведении и фокусе с клавиатуры в общем
компактном оформлении; пакет может обновлять дополнительные сведения в подсказке.
Для кнопок команд подсказка берёт актуальное сочетание из настроек клавиатуры;
переназначение сразу меняет подсказку, отключённое сочетание не показывается.
Начало перетаскивания скрывает её.

Селекторы модели и доступа можно перенести за ручку, появляющуюся при наведении
или фокусе. Нажатие ручки или ПКМ открывает выбор: слева под сообщением, справа
под сообщением или в шапке. Alt+←/→ меняют порядок внутри места размещения.
Расположение принадлежит поверхности `composer-model`/`composer-access`, поэтому
сохраняется при замене реализации. Перенос сохраняет экземпляр расширения и не меняет
сессию, к которой относятся модель и права; меню открывается в пределах окна.
Переключатели расширений сохраняют свои DOM-узлы при обновлении состояния, поэтому
фокус и анимация бегунка не сбрасываются. Доступные для добавления панели оформлены
скруглёнными карточками.

Подробный отчёт расхода и контекста находится в одноимённом пункте настроек. В рабочем меню «+» остаётся выбор вкладки.
Настройки интерфейса доступны при потере соединения с backend, хранятся в
localStorage и не меняют профиль агента.

Поставляются независимые пакеты:

- «Файлы» показывает дерево проекта и фильтр загруженных строк в отдельной вкладке.
  Первое чтение дерева и Git отложено до показа вкладки. Фильтрация и изменение
  ширины панелей объединяют события в один кадр.
  Ответы каталогов и Git объединяются в кадр обновления дерева. Строки с тем же
  путём и типом сохраняют DOM, фокус и выделение; исчезнувшие строки удаляются,
  а Git-статус обновляется внутри существующей строки.
  Дерево справа и содержимое слева находятся внутри одной вкладки; выбор
  документа заменяет просмотр, не создавая соседнюю вкладку. Граница областей
  регулируется мышью и стрелками; дерево можно скрыть. Просмотр показывает
  номера строк и Git diff, хранит последние 20 файлов и положение прокрутки.
  Каталоги загружаются при первом раскрытии, «Обновить» перечитывает дерево.
  Бинарные файлы и файлы больше 512 КиБ имеют явное состояние без текстового
  предпросмотра; показ каталога ограничен 1000 элементами с уведомлением.
  Ссылки и специальные файлы обозначаются в дереве, но не открываются.
  Редактирование файлов в этот этап не входит.
- «План», «Контекст» и «Сведения о сессии» используют общий `agent.session.read`:
  подписываются на состояние клиента, не опрашивая модель или отдельный HTTP
  endpoint. План показывает шаги и точки прогресса в компактном виде, при наведении
  раскрывает все шаги. Контекст показывает
  заполнение окна и порог автокомпакта, сведения — активность, число событий, вызовов инструментов и ожидающих ответов.
  «Сведения о сессии» представлены только иконкой с подробной подсказкой,
  отдельной вкладки у этого пакета нет. Модель, reasoning и режим доступа
  остаются у поля ввода, проект — в навигации.

- Панель «Сборка агента» читает публичный `GET /config`, показывает профиль и
  зарегистрированные инструменты. Обновляется при создании экземпляра и кнопкой
  «Обновить». Ошибка подключения отображается внутри панели.
- «Лимиты модели» читает публичный `GET /model/quota`: план, остаток каждого
  окна, момент сброса и credits. Обновляется при создании экземпляра, раз в минуту и кнопкой.
  Показывает время получения snapshot; провайдер может вернуть свой свежий cache.
  Для ChatGPT это cache до 30 секунд. Ошибка убирает старые остатки; `null`,
  пустые окна и исчерпанный лимит имеют разные состояния. Наступивший reset
  не превращает старые данные в полный остаток. Отключение отменяет fetch и таймер; сворачивание сохраняет обновления.
  Компактный бублик показывает остаток недельного окна (604800 секунд); если
  окон несколько, выбирается наименьший остаток. Отсутствие недельного окна
  или ошибка обозначаются «—». Наведение показывает остаток и сброс,
  нажатие раскрывает панель. Панель не содержит HTTP/auth деталей ChatGPT.
- «Заметки» хранит текст в клиенте и не использует агента; включается в списке
  расширений. Заметки общие для этого клиента, без привязки к проекту или сессии.
- «Расход» читает `GET /usage`: итоги токенов и оценку стоимости за чат или
  последний ход, разбивку по моделям и подробности отдельных model requests.
  Обновляется раз в пять секунд, пока отчёт виден и документ активен;
  скрытие приостанавливает опрос, повторный показ обновляет данные.
  При неизменном revision содержимое не
  пересоздаётся. Смена чата отменяет старый запрос и открывает новый отчёт.
  В разделе «Расход и контекст» (`?view=usage`)
  тот же пакет показывает полный список с выбором хода, модели и страницами
  по 20 запросов. Дополнительные фильтры
  отбирают ошибки, отмены, таймауты, запросы без результата или provider usage,
  обычные запросы и сжатие контекста. Поиск работает по ID запроса/хода и имени
  модели/провайдера. Сортировка доступна по времени начала, длительности,
  токенам и оценке стоимости; неизвестные значения идут последними.
  Фильтры списка не меняют итог выбранного периода: рядом показано количество
  найденных запросов. Номер запроса и хода сохраняет связь с порядком журнала.
  «Скачать JSON выборки» сохраняет все отобранные запросы, включая следующие
  страницы, с исходными ID, revision и фильтрами. Это метаданные расхода из
  публичного API; содержимое prompt/response и текст ошибок в них не входят.
  Включение боковой панели не управляет доступностью полного отчёта.

Страница анализа показывает название и идентификаторы выбранной сессии,
а «Открыть диалог» возвращает именно к ней. Выбор сессии для анализа не
переключает активный чат. Параметры URL `analysis_session` и `analysis_view`
сохраняют выбранную сессию и раздел при перезагрузке независимо от `session_dir`
активного чата. Вкладка «Контекст и инструменты» показывает последний снимок
сессии; фильтр хода в отчёте расхода не превращает его в исторический снимок.
DOM и состояние контекста сохраняются при переключении разделов. Обновление
контекста прекращается при скрытии вкладки или содержащего её workspace iframe;
повторный показ обновляет снимок. Запоздавший ответ
предыдущей сессии не заменяет текущий снимок.

У «Расхода» кнопка «Настроить» находится в списке расширений. Здесь задаются
свои цены в USD за миллион входных, выходных токенов, чтение и запись кэша,
порог длинного контекста и множители над порогом. Точное имя провайдера
необязательно: собственный тариф с провайдером имеет приоритет над тарифом для
любого провайдера, затем используется опубликованная цена известной модели.
Тарифы хранятся локально у расширения и применяются ко всему открытому отчёту,
включая прошлые запросы. Сброс своих тарифов — отдельное явное действие.

Поставляемые цены GPT-6 Astra и GPT-5.6 Sol/Terra/Luna (включая `gpt-5.6`)
зафиксированы по [Standard API OpenAI](https://developers.openai.com/api/docs/pricing)
на 2026-09-10. Превышение 272000 входных токенов удваивает вход и кэш,
умножает выход на 1,5 для всего запроса. Стоимость считается сначала по каждому
запросу, затем суммируется. Это оценка токенов по Standard API, для подписки —
условный эквивалент, не факт списания. Другие service tiers, региональные
надбавки, налоги и платные hosted tools в неё не входят. Неразмеченный вход
считается по обычной цене. Неизвестные тарифы и отсутствующий provider usage
отмечаются как неполнота итога, а не как нулевой расход. Кэш — часть входа,
рассуждения — часть выхода; повторно к общему числу токенов они не прибавляются.

Новые поставляемые пакеты показаны в настройках в списке «Доступные панели».
Их добавление не сбрасывает пользовательский порядок и не включает другие панели.
Удаление панели из списка сохраняет её данные. «Восстановить стандартный
список» заменяет состав, порядок и состояние панелей содержимым поставляемого
каталога; данные самих расширений остаются. Повреждённые настройки не исправляются
молча: клиент показывает ошибку и предлагает это явное восстановление.

Все пакеты используют общий lifecycle; workspace объявляется независимо от
компактного виджета. Переключение вкладок не анимирует
ширину и не переставляет корни содержимого в DOM. Новый mount нужен при смене
сессии, повторном включении или перезагрузке клиента.

## Пакет

Каталог может состоять из двух файлов:

```text
my-panel/
  extension.json
  panel.js
```

`extension.json`:

```json
{
  "apiVersion": 1,
  "id": "my-panel",
  "name": "Моя панель",
  "description": "Самостоятельная панель клиента",
  "entry": "./panel.js",
  "requires": []
}
```

`panel.js`:

```javascript
export function mount({ root, storage, signal }) {
  const input = document.createElement('textarea');
  input.setAttribute('aria-label', 'Текст');
  input.value = storage.get('text') ?? '';
  input.addEventListener('input', () => storage.set('text', input.value), { signal });
  root.append(input);
}
```

Раздайте папку статическим HTTP-сервером и добавьте URL `extension.json` в
клиент. Для отдельного origin сервер должен разрешать CORS для манифеста,
entry и импортов; JavaScript отдаётся с JS MIME type. Пересборка агента,
Leptos или desktop для такого подключения не нужна. После изменения кода
пакета перезагрузите клиент; hot reload внешних пакетов отсутствует.

Поставляемые пакеты находятся в `clients/app/ui/extensions/`.
`catalog.json` задаёт начальный список; после пользовательских изменений
используется сохранённый список. Trunk копирует каталог расширений, а desktop
встраивает те же assets. Dev-сборка следит за исходниками встроенных пакетов.
Установка из локального архива/папки и каталог пакетов с поиском пока не реализованы.

## Контракт UI API v1

Типы: `clients/app/ui/extensions/api.d.ts`. Неизвестная версия или неизвестные поля
манифеста отклоняются; старого compatibility reader нет. Необязательное поле
`presentation` принимает только `"widget"` (прокручиваемое содержимое вкладки, также при отсутствии поля)
или `"panel"` (содержимое занимает всю высоту вкладки).
Необязательное поле `surfaces` — непустой список поверхностей без повторов:
`"compact"`, `"workspace"`, `"settings"`, `"composer-model"`, `"composer-access"`.
При отсутствии объявлены `compact` и `workspace`. Пакет с
`"surfaces": ["compact"]` монтируется и получает обновления без вкладки и
без действия открытия workspace. Его `root` существует отдельно от видимой области.

Entry экспортирует `mount(context)`. Context содержит:

| Поле | Договор |
|---|---|
| `root` | Собственный `ShadowRoot` панели или `HTMLElement` страницы/селектора; клиент владеет размещением |
| `compact` | Собственный `ShadowRoot` интерактивного виджета у composer или в шапке; отсутствует без поверхности `compact` и в settings entry |
| `hover` | `set(text)` обновляет текст дополнительных сведений при наведении на компактную иконку; текст не исполняется как HTML |
| `panel` | `open()` открывает вкладку, `move("left" | "right")` меняет подсказку размещения и открывает вкладку; отсутствует без поверхности `workspace` и в settings entry |
| `panels` | `create(id, { title, location?, onClose? })` создаёт вкладку и возвращает `{ root, signal, show(), hide(), close() }`; `close()` освобождает вкладку, отменяет её signal и вызывает `onClose`; отсутствует в settings entry |
| `services` | Только интерфейсы из `requires`; отсутствие интерфейса блокирует эту панель до исполнения entry |
| `storage` | `get/set/remove` строковых значений и `subscribe` на изменения в пространстве `id` расширения |
| `signal` | Отмена при отключении, удалении, ошибке mount или закрытии host; панели дополнительно размонтируются при смене сессии |

`mount` возвращает `undefined`, функцию очистки или Promise одного из этих
значений. DOM listeners и fetch связываются с `signal`; собственные timers и
подписки освобождаются в функции очистки. Она вызывается один раз. Если панель
отключена во время загрузки entry, mount не вызывается; если отключена во время
асинхронного mount, signal отменяется сразу, а поздняя функция очистки выполняется
при завершении mount. Extension обязан завершать mount и учитывать отмену.
Ошибка загрузки/mount одной панели не останавливает соседние панели или чат.
Сохраняющиеся страницы настроек и селекторы читают текущую сессию через
перепривязываемый service adapter; поздний ответ предыдущей сессии отклоняется.

Дополнительные вкладки принадлежат экземпляру расширения и используют его
capabilities; новых прав агента они не предоставляют. Отключение, удаление,
retry, ошибка владельца, смена сессии или unmount удаляют все его вкладки.
`hide()` сохраняет корень, `close()` освобождает его. Обработчики документа
следует связывать с signal самой вкладки, чтобы закрытие освобождало их до
завершения родительского расширения.

Детали субагентов открываются в принадлежащих клиенту вкладках этой же области.
В чате остаётся короткая строка роли и статуса; описание задачи, действия,
аргументы, результаты инструментов и результат родительского вызова находятся
во вкладке. Её содержимое монтируется при открытии; закрытие освобождает
подписки деталей. Approval остаётся доступным в основном чате. Здесь показывается
существующая проекция событий: отдельный полный текст переписки дочернего агента
в текущий transcript API не входит.

Манифест может объявить отдельный entry настроек:
`"settings": { "entry": "./settings.js", "requires": [] }`. Он имеет тот же
контракт `mount(context)`, собственный список интерфейсов и общее с панелью
пространство storage. Загрузчик исполняет его только после «Настроить»;
открытие списка расширений не перезапускает panel entry и не исполняет settings
entry. Включение или установка активной панели запускает её в живом workspace. Удаление пакета и закрытие клиента завершают его
lifecycle. `storage.subscribe(callback)` сообщает об изменениях данных этого
пакета в том же клиенте и возвращает обязательную функцию отписки.

Shadow DOM отделяет оформление содержимого от CSS остального клиента. Панель
наследует общие переменные цветов, шрифтов и скруглений, например `--text-main`,
`--text-muted`, `--bg-panel`, `--accent-blue`, `--font-sans`, `--radius-inner`.
Оболочка задаёт небольшой базовый стиль; пакет может добавить собственный CSS.

## Доступ К Агенту

Общий загрузчик `host.js` получает интерфейсы от клиента через
`mountExtensions(root, serviceFactories)`. У него нет зависимости от агента.
`registry.js` хранит состав и состояние расширений; в текущей витрине один
экземпляр реестра живёт между SPA-переходами. Манифесты загружаются один раз
за открытие клиента; перезагрузка страницы перечитывает их. `host.js` отвечает
за показ панелей, `settings.js` — за управление. Список настроек не исполняет
entry панелей; отдельный settings entry загружается по кнопке «Настроить».
Подписки представлений снимаются при unmount; внешний автономный
host может создать собственный реестр или передать общий через `options.registry`.

`web-adapter.js` связывает конкретную витрину с её HTTP transport и предоставляет
интерфейсы `agent.config.read`, `agent.config.builder`, `agent.model.quota.read`,
`agent.usage.read`, `agent.session.read` и `agent.workspace.read`:

```javascript
const config = await services['agent.config.read'].read();
const quota = await services['agent.model.quota.read'].read();
const usage = await services['agent.usage.read'].read();
```

Укажите используемые интерфейсы в `requires` манифеста.
Ответы — неизменённый JSON публичных `GET /config` и `GET /model/quota`.
Клиентский transport добавляет `?session_dir=<path>` к config, quota и usage
запросам по выбору чата конкретного окна. Сам пакет не выбирает глобальную
session на сервере; открытие другого окна не меняет адрес этих чтений.
Usage reader отдаёт `SessionUsageSnapshot` из публичного `GET /usage` для
выбранного чата либо `null`, если runtime не ведёт canonical journal.
Quota reader возвращает snapshot из `api.d.ts` или `null` (не поддерживается);
ошибки HTTP/transport отклоняют Promise. Client transport добавляет
credential и связывает HTTP fetch с lifetime панели; расширение не получает
credential через этот интерфейс. Другой клиент может предоставить тот же
интерфейс своим transport-адаптером. Автономный пакет использует пустой `requires`.

`agent.config.builder` читает публичный `GET /config/builder`, сохраняет
профиль через `POST /config/builder` и читает `GET /config/history` выбранной
сессии. Это действие владельца
UI: сервер строит и проверяет полную сборку до записи профиля, а
не дающий прав модулям агента канал. Пакет запрашивает интерфейс в `requires`
явно; его наличие у поставляемых страниц агента не даёт им особых прав.

`agent.session.read` возвращает копию проекции клиента через `read()` и
`subscribe(callback)` с немедленным первым уведомлением. Изменения transcript,
статуса и модели поступают из существующего stream; подписка снимается при отмене.
`agent.workspace.read` предоставляет `list(relativePath)` и `read(relativePath)`
через публичные `/workspace/list` и `/workspace/file`; корень берётся из
адресованной сессии, credential остаётся в transport. Формы ответов и состояния
предпросмотра описаны в `api.d.ts`. Это чтение по действию владельца UI, не
исполнение agent tool и не новая authority для process modules.

Тот же интерфейс предоставляет `changes()` и `diff(relativePath)` для чтения
изменений Git относительно `HEAD`. `changes()` возвращает
`{ repository: boolean, entries: [{ path, status }], truncated: boolean }`,
где `status` — `added`, `modified`, `deleted`, `renamed`, `untracked` или
`conflict`. `repository: false` явно обозначает отсутствие репозитория,
`truncated` — неполный список. `diff(path)` возвращает
`{ path, kind, patch: string | null }`: `kind` принимает `text`, `binary`,
`too_large` или `unavailable`; текстовый patch доступен только для `text`.

Новые действия и источники данных добавляются через конкретные договоры клиента
или публичный API агента. Здесь нет нового behavior slot, регистрации UI внутри
процессного модуля или универсального вызова внутренностей modules. Backend quota проходит
через общий слот `model`, не зависит от пакета панели и доступен через
публичный API агента.

проверяет расширения, перенос панелей, меню и геометрию без сценариев анализа
расхода и очереди. `--stability-only` проверяет длинную историю, прокрутку,
стрим, переподключение, отмену и освобождение таймера при переходах между экранами,
сохранение черновика и позиции чтения во время ответа. Он также проверяет, что
буфер ответа не переходит между сессиями, а ошибка открытия другого чата
восстанавливает прежнее подключение, историю и черновик с видимым уведомлением.

запоздавшее событие прокрутки и следующий кадр не должны возвращать читателя вниз.

диалог, фильтрацию без подмены итогов, стабильные ID, сортировку неизвестных
значений, JSON выборки и узкий экран. Основные данные приходят из настоящего
журнала; error/unfinished/compactor комбинации дополнительно подставляются
управляемым browser fixture. Скриншоты — `/tmp/proteus-session-analysis.png`
и `/tmp/proteus-analysis-mobile.png`. `session_checks.py` загружает 240 записей истории через настоящий
клиент, затем проверяет реальный SSE-ответ, сохранение DOM старых карточек,
автопрокрутку и чтение истории во время стрима. Повторные подключения должны
закрывать прежние EventSource, снимать их обработчики и перечитывать историю. Rust regression
проверяет отдельные подписки на 2000 сообщениях: 20 изменений одной записи
дают 20 обновлений её карточки и не пересобирают порядок ленты. Layout smoke
использует длинную синтетическую ленту, проверяет однократное изменение ширины
панелей без покадровой анимации ширины переписки, перенос фокуса,
отсутствие localStorage writes во время drag,
автоматический рост/сжатие поля ввода, перенос длинных строк, доступность меню
на узком экране, отступ ленты по высоте композера и сохранение рабочих областей. Время кадров печатается как диагностическое
измерение, а не как универсальный порог для любого оборудования.

`python3 clients/app/ui/tests/extensions_browser.py --placement-only` проверяет
независимое размещение виджетов, сохранение их экземпляров при переносе и скрытии,
откат при ошибке записи, восстановление после reload и размеры подсказок/меню.

`python3 clients/app/ui/tests/popovers_webkit.py` проверяет размеры меню проекта,
чата и подсказок в WebKitGTK 4.1 — движке Linux desktop. Проверяет также
размещение у нижнего края окна; требует Python GI, GTK3, WebKit2 и Xvfb.

Проверки страниц расширений и селекторов: `node --test clients/app/ui/tests/extensions/*.test.mjs`,
`python3 -B clients/app/ui/tests/extensions_browser.py --modules-only`.
Регрессия геометрии селектора, ползунка и закрытия вкладок в native engine:

Браузерный сценарий проверяет перенос и отмену, сохранение DOM/iframe/черновика,
разделитель, объединение, восстановление раскладки и обновление сочетаний в
подсказке. WebKit проверяет ту же геометрию, выход вкладки без смены её позиции,
сохранение прокрутки и документа iframe в движке desktop.
Общие read-сервисы агента ожидают первое подключение с отменой
по `AbortSignal`; запоздавший ответ предыдущей сессии отклоняется.

Встроенная диагностика сохраняет документ при переключении вкладок. При смене
сессии видимая страница обновляет подключение сразу, а скрытые страницы применяют
только последнее подключение при открытии: одновременной перезагрузки всех
посещённых разделов нет. Возврат из диагностики в текущий чат выполняется
без перезагрузки клиента. Ссылка на другую сессию явно открывает чат через
одноразовый `workspace_view=chat`; при запуске параметр удаляется из адреса.
